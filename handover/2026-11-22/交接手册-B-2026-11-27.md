## 二、发布网站操作手册（重点）

> 前置条件（缺一不可）：① main 冻结 ② 11-24 三人封版签字 ③ 用户明确"可以发布"的信号
> 红线：**发布必须等封版；公开必须等全队走查通过**

### 步骤 1 · 构建（发布源目录内）
```bash
cd "C:/Users/20824/Documents/Qoder/2026-11-21/3f7a5378/fragment-notes-release"
git pull --ff-only                 # 同步最终 main
npm install --ignore-scripts --registry=https://registry.npmmirror.com
npm run build                      # 产出 dist/
git restore package-lock.json       # npm 会改 lock（环境噪音），还原保持干净
```
打包红线自查：`api/` 内只有 `index.ts` + `generate-deck.ts`（dev/ 在根目录不在包内）；`.env`、`node_modules` 不入包；`dist/` 内无 sourcemap、无密钥串。

### 步骤 2 · prepare（打包上传成草稿，不对外可见）
MCP 工具 `prepare_site`，参数**逐字照抄**：
```
actionId        = 新 UUID（内容变了必须换新 action；同一 action 重试 = 恢复，不是重传）
projectRoot     = C:\Users\20824\Documents\Qoder\2026-11-21\3f7a5378\fragment-notes-release
webDirectory    = dist
functionDirectory = api
spa             = true
secretNames     = ["AI_API_KEY"]
projectId       = 01a1f3f6-3a6b-791b-84fa-11ba6076f380
```
- 返回 `descriptorStatus: pending` 时：用**同一 actionId + 完全相同入参**重试以恢复 descriptor（不要换 action）
- 平台侧偶发 `sites_upload_unavailable`：等几分钟用同一 action 重试即可，**不要新建站点**

### 步骤 3 · 等就绪
MCP 工具 `get_publish_status`，传 actionId，直到 `artifactReady && dependenciesReady && canPublish == true`、`blockers` 为空。
若卡在 `sites_deployment_not_ready`：按提示用 `get_operation`（传 verificationOperationId）查进度，**保留 action**。

### 步骤 4 · 发布
MCP 工具 `publish_site`，传**同一 actionId**；之后轮询 `get_publish_status` 直到 `published: true`。
Desktop 端发布成功后必须调用 `show_publish_confirmation`（同一 actionId）完成交付展示，它**不会**替你发布。

### 步骤 5 · 公网真机验证（P2-2，B 的活）
1. 无痕打开站点 → 上传**真实资料**（照片 / 多页 PDF / HTML）→ 确认生成结构化碎片卡片
2. 点「填入示例课堂片段」→ 确认走真实 AI
3. 触发一次**比喻追问**（analogy 路由）确认 200
4. 检查 Function 日志（`get_function_logs`）：**不得出现密钥或原始上游异常泄漏**；我们的日志只打 model/host/status/字符数
5. 确认自带 Key 场景可用（AI 设置里填 Key → 请求头带 Authorization 到转发层）

### 步骤 6 · 全队无痕走查（P2-4，A 组织 / C 领移动端）
示例 → 翻卡 → 小测 → 错题 → 刷新 → 换主题；阻断项回 B 修复重发，非阻断项记豁免。

### 步骤 8 · 回滚演练（P2-6，B 的活）

## 五、已知坑（别再踩）
1. **git 通道稳，REST API 通道不稳**：Steam++ 的 `api.github.com` 解析会间歇返回垃圾 IP → 502；`git push/ls-remote` 全程正常。建 Issue/评论失败就重试，或等加速器重启。
2. **curl 需要 `--ssl-no-revoke`**（schannel 吊销检查失败），并且 `2>&1` 只能放在命令末尾、后面不能接管道，否则被协作钩子拦。
3. **Sites prepare 的 projectRoot 必须在当前会话目录内**；桌面/其他目录报 `sites_current_session_required`。
4. **内容改了必须换新 actionId**；同一 action 重试 = 恢复。
5. **绝不新建站点**（createNewSite）——会多出一个站点与地址；复用既定 projectId/siteId。
6. **仓库是 public**：任何上传内容都要过一遍密钥/本机路径扫描再推。
7. **发布必须等封版、公开必须等走查**；草稿（prepare）可以提前做，但不可 publish。
8. 隐私模式/配额超限时，浏览器会禁 localStorage —— 用 `Storage.prototype` 注入模拟复测，不要只在正常环境点一遍。
